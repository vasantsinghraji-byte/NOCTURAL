# Nabz staging on AWS App Runner (no domain needed)

| Part | Where |
|---|---|
| Website (Next.js) | App Runner `nabz-staging-web`, e.g. `https://79fkmxu8w3.ap-south-1.awsapprunner.com` |
| API (Express) | App Runner `nabz-staging-api`, e.g. `https://tiuh3tvxsa.ap-south-1.awsapprunner.com` |
| Database | MongoDB Atlas `nabz-staging` (AWS Mumbai), database `nabz` |
| Images | ECR `nabz-staging-api` / `nabz-staging-web`, built by CodeBuild `nabz-staging-images` |
| Uploads | private S3 `nabz-staging-uploads-<account>` |
| Terraform state | S3 `nabz-tfstate-<account>` (key `staging/apprunner.tfstate`) |

The browser only talks to the website; `/api/*` is proxied to the API (see
`frontends/web/next.config.mjs`). That keeps the API's `SameSite=strict`
cookies first-party without a shared domain. The mobile apps call the API URL directly.

## Secrets (AWS Secrets Manager, region ap-south-1)
- `nabz/staging/MONGODB_URI`: Atlas connection string, created by hand (never in git or chat).
- `nabz/staging/JWT_SECRET`, `JWT_REFRESH_SECRET`, `ENCRYPTION_KEY`: generated by Terraform.
- `nabz/staging/ADMIN_PASSWORD`: staging admin password (read it in the console:
  Secrets Manager → the secret → *Retrieve secret value*). Admins must set up
  two-step verification (authenticator app) at first sign-in.

## Deploy a new version
```bash
export AWS_PROFILE=nabz AWS_REGION=ap-south-1
# 1. zip the working tree (no node_modules, no .env) and upload
#    (see the zip command used in the deploy session, or `git archive`)
aws s3 cp source.zip s3://nabz-staging-build-<account>/source.zip
# 2. build; App Runner redeploys automatically when :latest changes
aws codebuild start-build --project-name nabz-staging-images \
  --environment-variables-override name=TARGET,value=api,type=PLAINTEXT
aws codebuild start-build --project-name nabz-staging-images \
  --environment-variables-override name=TARGET,value=web,type=PLAINTEXT \
  name=API_ORIGIN,value=https://<api host>,type=PLAINTEXT
```

## First-time setup (already done once)
1. State bucket `nabz-tfstate-<account>` (versioned, encrypted, private).
2. `terraform init -backend-config=backend.hcl`
3. `terraform apply` → registries, buckets, CodeBuild, secrets.
4. Build the api image → `terraform apply -var create_api=true`.
5. Build the web image with `API_ORIGIN` = api URL → `terraform apply -var create_api=true -var create_web=true`
   (this also sets the API's `ALLOWED_ORIGINS` to the website URL).
6. Database: run `scripts/add-indexes.js`, `seedServiceCatalog.js`, `seedPharmacyMarketplace.js`
   (needs `SEED_DEMO_PASSWORD`), `seedAdmin.js` from a laptop with `MONGODB_URI` from the secret
   (insert `/nabz` as the database path for these scripts).

Always pass `-var create_api=true -var create_web=true` on later applies, or Terraform will delete the services.

## Known limits (staging)
- ⚠️ Atlas network access is `0.0.0.0/0` because App Runner has no fixed egress IP. Protected by the
  database password + TLS. Production: fixed egress (VPC connector + NAT) or Atlas PrivateLink.
- Website logins are rate-limited per client IP as seen through the website's proxy; heavy
  login testing from many users at once may hit the 5-per-15-minutes auth limit sooner.
- Adding a domain later: App Runner → service → *Custom domains* (both services), then update
  `ALLOWED_ORIGINS`/`APP_URL` and rebuild the web image with the new API origin.
